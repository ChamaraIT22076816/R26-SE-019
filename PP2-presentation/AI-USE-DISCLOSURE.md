## 1. Summary

I used AI coding assistants — principally **Anthropic's Claude (Claude Code)** —
throughout the implementation of this component. I used them as a **development
tool under my direction**, in the way a developer uses a compiler, a linter or
Stack Overflow: they accelerated writing and refactoring code and drafting
documentation.

**They were not used to generate research results.** Every number reported in
this project is produced by executing code against real data. No figure was
written by a language model, and no figure is quoted from one. The evaluation
protocol, the metrics, the dataset choices and the interpretation of the results
are mine.

I take full responsibility for all submitted work, including any code an
assistant helped produce. I have read and can explain every part of the system.

## 3. Where AI assistance was **not** used

- **Research design.** The scope, the decision to build a DTW-based grader
  rather than a classifier, and the reasoning that made that the right tool are
  mine.
- **Metric selection and interpretation.** Including the decision to report ROC
  AUC alongside a stated majority-class baseline rather than a bare accuracy
  figure.
- **The decision to reject a measured improvement.** A grid search found the
  best separation at `W_SHAPE` = 1.0 (78.6%). I rejected it and shipped 0.8
  (74.2%) because the search optimises a classification objective while the
  scorer grades a known sign, and movement is a phonological parameter of SSL.
  That judgement is mine and is the kind of decision an assistant will not make
  for you.
- **Any reported number.** All figures come from executing the code. They are
  regenerated by the test suite and can be reproduced live — see
  [EVIDENCE.md](EVIDENCE.md).
- **Sign-language content.** No SSL vocabulary, gloss, handshape or sentence
  order was generated by AI at any point. Every sign in the system comes from a
  published corpus performed by real signers. Glosses are the corpora's own
  labels. Anything requiring a certified signer is deferred to the School for
  the Deaf, Ratmalana. This was an explicit rule for the whole component,
  because a plausible-sounding invented sign is worse than a missing one.

## 4. Verification — how I satisfied myself the work is sound

AI-assisted code needs more verification than hand-written code, not less. What
this component does about that:

1. **129 automated tests** covering scoring invariances (translation, zoom,
   signing speed, capture resolution), handedness mirroring, wrong-handshape and
   wrong-trajectory discrimination, and the feedback pointing at the correct
   finger. These are executable assertions, not claims.
2. **Every reported figure is generated, never typed.** The reports carry
   *"Generated by … Do not edit by hand."* and are rewritten by the test that
   measures them, so a quoted number and its code cannot disagree.
3. **Independent re-derivation.** The chart data is exported by a separate
   routine that reproduces each existing test's sampling protocol and calls the
   same scorer. It agrees with the committed reports to three decimal places.
4. **Assistant output was rejected where it was wrong.** Documented examples,
   all preserved in the repository:
   - a proposed velocity-based trajectory feature *improved* separation from
     73.5% to 75.5% and was **reverted** after a unit test showed a learner
     moving in entirely the wrong direction still scored 100;
   - the original score anchors (0.05 / 0.35) were assumed values that put
     `D_ZERO` below the median correct rendition, so a correct attempt scored
     zero — found by calibrating against data and replaced with fitted values;
   - a benchmark initially timed a workload roughly a third of the real size by
     using the reference as the attempt, ignoring that a learner's take carries
     far more frames.
5. **I can explain and modify any part of it.** That is the working test of
   whether assistance stayed assistance.
